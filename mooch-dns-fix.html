mooch · transparent mode

Why DNS broke — and how it's fixed

Routing your Mac through the phone was the easy half. Getting names to resolve once Wi-Fi is off was the half that fought back. Here's the problem in plain terms, the fix, and exactly what to run.

Right now: everything is clean. No tunnel running · no leftover routes or DNS overrides · Wi-Fi is your uplink · Tailscale DNS normal. Safe to start a fresh test.

01 The problem

Two things quietly broke DNS in the one state that matters: Wi-Fi off, phone on.

macOS ties DNS to a network service. The old fix set DNS on the Wi-Fi service. The moment you turn Wi-Fi off, macOS tears that service down — and your DNS setting vanishes with it. So the exact situation you want (phone-only) is the one where DNS dies.

And your real resolver isn't Wi-Fi — it's Tailscale. Tailscale owns the top resolver and forwards lookups to whatever it captured underneath: your home router, 192.168.1.1. With Wi-Fi off, the router is unreachable, so every name fails — even though traffic itself is happily flowing through the phone.

02 The fix

Give DNS its own home on the tunnel, and move Tailscale out of the way just while mooch runs.

1 · DNS now lives on the tunnel, not on Wi-Fi. mooch registers 1.1.1.1 as its own network service bound to the utun interface (via scutil — the same trick the C tether uses). It doesn't care whether Wi-Fi is on or off, and it evaporates on reboot so it can never get stuck.

2 · Tailscale steps aside for the session. While the tunnel is up, mooch runs tailscale set --accept-dns=false so your 1.1.1.1 becomes the resolver in charge. Your VPN stays connected — only DNS management is paused — and it's turned back on the instant you stop.

Two new safety tools came with it:

/tmp/mooch.log — a timestamped log of everything mooch does (route steals, DNS changes, teardown), so you can see what happened as you flip Wi-Fi.  ·  sudo ./mooch.sh dns-reset — one command that un-sticks DNS no matter what: clears the override, resets services to DHCP, turns Tailscale DNS back on.

05 If anything feels stuck

In rough order. You cannot brick yourself out — the last one always works.

tail -f /tmp/mooch.log

Watch exactly what mooch is doing, live, in a spare window.

sudo ./mooch.sh dns-reset

Names won't resolve? This un-sticks DNS: clears the override, DHCP back, Tailscale DNS on.

sudo ./mooch.sh panic

Force-remove everything — tunnel, routes, DNS, proxies — from any window.

Reboot

The guaranteed reset. Routing and the DNS override are gone on restart, always.

One honest caveat: Tailscale's paused-DNS pref is the single thing that outlives a reboot. If mooch ever crashes mid-run, a plain sudo ./mooch.sh dns-reset (or tailscale set --accept-dns=true) puts it right.
